# Coach: Memory, Stats and a Fuller Journey Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record every failure, hint, solution and review in the journey; give the chat agent a local memory about me; add stats and a weekly read, all built from my own data.

**Architecture:**
- `journey.ps1` gains the failure fields, hash-named snapshots, coach events and the new Status rules.
- A new `memory.ps1` library holds the local memory store, with ageing and dedup.
- Two new scripts, `lc-coach.ps1` (writes) and `lc-stats.ps1` (reads), are what the agent calls. `lc-context.ps1` prints memory.
- CLAUDE.md tells the agent when to call each one.

**Tech Stack:** Windows PowerShell 5.1, the existing self-test runner (`lc/tests/run-all.ps1`, `Assert-*` in `lc/tests/assert.ps1`).

**Spec:** `docs/2026-10-18-coach-design.md`

## Global Constraints
- **Scripts:** Windows PowerShell 5.1, ASCII-only `.ps1` files, UTF-8 without BOM for every data file written.
- **Network and git:** no network calls in any new code. `lc-coach.ps1` and `lc-stats.ps1` never commit or push.
- **Local data:** memory, coach state and weekly reads live under `<JourneyRoot>/local/`. `.gitignore` gets `journey/local/`.
- **Parameters:** every new script takes `-JourneyRoot` (default `<dsa>/journey`). Self-tests always pass a temp root and never touch the real `journey/`.
- **Text cuts:** failure values are cut to 200 characters (197 kept, then `...`). Memory text is 1-300 characters, newlines collapsed to spaces.
- **Ageing and status thresholds:** habit becomes `improving` after 14 days and `resolved` after 28; a problem is `failed` after 7 days.
- **Writing style:** user-facing text and docs in plain no-ai-slop style. No emoji, no exclamation marks.
- **Testing:** focused suites only, with `run-all.ps1 -Only <name>`. The full suite runs once at the end.

## Review Focus
1. **No LeetCode username:** a problem that passed locally must stay `passed locally` after 7 days, never `failed`. Test in Task 2.
2. **A malformed line in `memory.jsonl`** (hand edit or a cut write) is skipped. `lc-context`, `lc-coach memory` and `remember` still work. Test in Task 3.
3. **`lc-coach hint` for a problem that was never run,** where the file exists but has no events: it still writes the event (hash of the file now) and doesn't fail on the journey.md update. Test in Task 2.
4. **Quotes, backslashes, `|` or newlines** in memory text, review pattern or failure values survive the JSON round trip and don't break journey.md rows. Test in Tasks 1 and 3.
5. **A stale journey.md:** a problem crosses the 7-day line without any run. `lc-stats` rebuilds the table, so the row shows `failed`. Test in Task 4.

**Interfaces:**

  - `lc-coach.ps1` commands:
    - `remember -Kind <kind> -Text <text> [-Evidence 'slug:ref',...] [-Source coach|user] [-Until yyyy-MM-dd] [-Replaces <id>]`;
    - `forget -Id`;
    - `edit -Id -Text`;
    - `resolve -Id`;
    - `memory`;
    - `read -Slug`, which stores the slug's latest `solved` src_hash in `coach-state.json`;
    - `weekly -Text <markdown>`, which writes `local/weekly/<Monday>.md`.
- Consumes: `Read-LcEvents`, from Task 2's `lc-coach.ps1` skeleton.
